# 발로란트 무기 데이터 (20종)

발로란트의 모든 총을 `UValorWeaponDataAsset` 에셋(`/Game/Valor/DataAsset/DA_<무기>`)으로 만든다.
공개된 수치는 가능한 한 모두 담는다. 코드가 필요한 기능(산탄, 점사, 가속 등)은 **데이터 필드만 먼저** 만들어 두고, 해당 총을 구현할 때 연결한다.

- 수치 원본: `Source/ValorEditor/Private/Weapons/ValorWeaponPresets.cpp` (값마다 [공식]/[추정] 표시)
- 에셋 생성: 커맨드렛 `ValorGenerateWeaponAssets` (에디터 전용 모듈 `ValorEditor`)
- 에셋마다 **Source Notes**(에디터 전용 필드)에 어떤 값이 공식이고 어떤 값이 추정인지 적혀 있다.
- 밴달 반동 모델과 측정 방법: [VandalRecoil.md](VandalRecoil.md)

## 1. 구현 상태

20종 모두 사격이 동작한다. 무기별 특수 동작은 아래와 같다(규칙은 5-1장).

| 동작 | 무기 |
|---|---|
| 점사 | 불독 ADS 3점사, 스팅어 ADS 4점사 |
| 산탄 | 쇼티 15펠릿, 저지 12펠릿, 버키 15펠릿, 클래식 우클릭 3펠릿 |
| 우클릭 = 보조 공격 | 클래식(3펠릿 산탄), 버키(7.5m에서 터지는 캐니스터) |
| 발사 속도 가속 | 오딘 힙파이어 12 → 15.6 |
| 저격 조준 | 토글 조준, 오퍼레이터 2단 줌(2.5배 → 5배), 조준경 오버레이 |
| 쏘면 조준 해제 | 오퍼레이터, 마샬(아웃로는 유지) |

공통으로 아직 없는 것:
- 무기별 이동 속도(`MoveSpeedMultiplier`, 조준 중 감속 포함)
- 소음기 효과(`bSilenced`)
- 장착 시간(`EquipTimeSeconds`, 교체 직후 사격 금지)
- 한 발씩 장전(`ReloadPerRoundSeconds`, 버키·마샬), 아웃로 1발 장전
- 가격(`Cost`, 상점 시스템)
- 점사 ADS를 올리는 동안 사격 지연(4.07)

## 2. 에셋 생성 방법

에디터를 닫고 실행한다(에디터가 켜져 있으면 Live Coding 때문에 빌드가 막힌다).

1. 에디터 빌드:
   ```
   "D:/Unreal Projects/Unreal5/Engine/Build/BatchFiles/Build.bat" ValorEditor Win64 Development -Project="D:/GitHub/Valor/Valor.uproject" -WaitMutex
   ```
2. 에셋 생성:
   ```
   "D:/Unreal Projects/Unreal5/Engine/Binaries/Win64/UnrealEditor-Cmd.exe" "D:/GitHub/Valor/Valor.uproject" -run=ValorGenerateWeaponAssets -unattended -nopause
   ```

옵션:
- 기본: 이미 있는 에셋(`DA_Vandal` 등)은 건너뛴다. 에디터에서 튜닝한 값을 보호하기 위해서다.
- `-overwrite`: 수치를 프리셋 값으로 되돌린다. 에디터에서 연결한 연출 참조(발사 몽타주·이펙트·그립 소켓)는 유지한다.
- `-only=Phantom,Spectre`: 일부 무기만 만든다.

테스트: 콘솔 `Automation RunTests Valor.` — 16개.
- 스프레이 7개
- 발사 모드 4개: 점사 간격, 오딘 가속, 산탄 퍼짐, 발사 요청 직렬화
- 줍기 1개: 조준선 선택
- 프리셋 3개: 공식 수치, 커브 형태, 무기별 규칙
- 에셋 로드 1개: `DA_*` 20개가 로드되는지 확인한다. 수치가 프리셋과 다르면 경고만 낸다(튜닝한 값일 수 있어서).

밴달 동작은 바뀌지 않는다. 옮기거나 추가한 필드의 기본값이 모두 밴달 값이다.

## 5. 반동 수치 — 공식 구조값과 추정 크기

라이엇은 반동의 **구조**(보호 탄, 수평 전환 시간·확률, 회복 시간, 탭 효율, 탄퍼짐 증가 지점)만 공개한다. **크기**(몇 도 올라가나)는 공개하지 않는다.
밴달만 실제 영상을 프레임 단위로 측정했다. 나머지는 아래 방법으로 추정했다.

| 무기 | 보호 탄 | 수평 전환 시간 / 확률 | 회복(초) | 탭 효율 | 수직 최대 | 수평 진폭 |
|---|---|---|---|---|---|---|
| Vandal | 6 | 0.6 / 10% | 0.375 | 6 | 8.95° (실측) | ±2.8° (실측) |
| **Phantom** | 8 | 0.6 / 10% | 0.35 | 4 | 약 8.0° (추정) | ±2.4° (추정) |
| **Spectre** | 5 | 0.28 / 10%* | 0.35* | 3 | 약 5.1° (추정) | ±2.05° (추정) |
| Bulldog | 6* | 0.6 / 10% | 0.35 | 4* | 약 7.9° (추정) | ±2.2° (추정) |
| Stinger | 0* | 0.4 / 10%* | 0.4 | 3* | 약 6.7° (추정) | ±2.7° (추정) |
| Frenzy | 3* | 0.4 / 10%* | 0.35* | 3* | 약 4.7° (5발째 최대) | ±1.7° (추정) |
| Ares | 4* | 0.6 / 10%* | 0.4* | 3* | 약 4.3° (추정) | ±2.5° (추정) |
| Odin | 4* | 0.6 / 10%* | 0.4* | 3* | 약 3.7° (추정) | ±3.5° (추정) |

`*` = 공개 수치가 없어 추정한 값(보호 탄 `*`는 AimFinder 값).

그 밖의 무기:
- 워든: 반동이 아직 공개되지 않아(2026-09-22 출시) 밴달 값을 임시로 쓴다.
- 권총·가디언·저지: 연타 반동을 추정값으로 둔다. 밴딧은 13.00 공식값(회복 0.4초, 탭 효율 4, 최대 수직 반동 3°)을 쓴다.
- 마샬·오퍼레이터·쇼티·버키: 스프레이가 없다(첫 발 = 최대 탄퍼짐). 화면 반동은 카메라 킥 연출로만 보여 준다.
- 아웃로(13.01): 조준 상태에서 두 번째 발에 탄퍼짐 2.25°와 반동 4.0°가 붙는다.
  - 공식 "회복 0.15초"는 다시 쏠 수 있게 된 뒤 0.15초로 해석했다(해석, 첫 발 뒤 약 0.51초).

공식 규칙을 커브에 반영한 무기:
- 스펙터: 3·6·8번째 발에서 탄퍼짐이 계단식으로 커진다(4.0).
- 프렌지: 5번째 발에서 탄퍼짐·반동이 최대다(6.11).
- 아레스: 13발 동안 탄퍼짐이 1.0 → 0.7로 줄어든다(4.01).
- 클래식 우클릭: 연속 점사 탄퍼짐이 1.9 → 2.5 → 6.0으로 뛴다(2.0).
- 스펙터: 달리기 수평 반동 ×1.5(4.0).

| 동작 | 규칙 | 서버/클라 |
|---|---|---|
| 점사(불독·스팅어 ADS) | 한 번 누르면 버튼을 떼도 끝까지 쏜다. 누르고 있으면 점사를 반복한다. 점사 안 간격은 `1/BurstFireRate`, 점사 주기는 `BurstCount/FireRate`다(불독 0.475초, 스팅어 0.472초). | 발마다 "다음 발까지 최소 간격"을 같은 규칙으로 계산한다. 서버는 이 값으로 연사 속도를 검증하고 클라는 예약한다. |
| 오딘 가속 | 끊기지 않고 쏜 시간에 비례해 12 → 15.6발/초(1초, 추정)로 오른다. 기본 간격의 1.5배 넘게 끊기면 처음부터 다시 시작한다. | 같은 방식 |
| 산탄 | 반동은 한 번 적용하고, 펠릿마다 `발 시드 + 펠릿 번호`로 탄퍼짐 원 안의 위치를 따로 뽑는다. 한 대상에 맞은 펠릿 피해는 합산해 한 번에 준다. | 서버와 예측 클라가 같은 모양을 만들고, 판정은 서버가 펠릿마다 랙 보상으로 한다. |
| 한 발 여러 탄 | 클래식 우클릭은 3탄(3펠릿)을 쓴다. 남은 탄이 모자라면 남은 만큼만 쏜다. | 클라는 예측 탄약에서 비행 중인 탄 수를 뺀다. |
| 버키 캐니스터 | 반동 방향(퍼짐 없음)으로 7.5m를 날아가 터지고, 그 지점에서 5펠릿이 퍼진다(2.0°). 터지기 전에 맞으면 펠릿 1알 피해만 준다. | 서버 판정. 멀티캐스트로 폭발 지점과 탄착을 보낸다. |
| 우클릭 | ADS 총은 조준, 클래식·버키는 보조 공격(반자동), 우클릭이 없는 총은 아무 동작도 하지 않는다. | 발사 요청에 "우클릭으로 쐈는지" 1비트를 담는다. 조준 총은 이 비트를 무시하고 서버의 조준 상태를 쓴다. |
| 저격 조준 | 기본은 토글이다(오퍼레이터: 2.5배 → 5배 → 해제). 2단 줌은 FOV만 바뀌고 정확도는 같다. | 서버는 조준 여부만 알고, 줌 단계는 로컬 화면 전용이다. |
| 쏘면 조준 해제 | 오퍼레이터·마샬은 발사하면 조준이 풀린다. 아웃로는 유지된다. "자동 재조준" 설정을 켜면 발사 간격 뒤 다시 조준한다. | 서버는 조준 어빌리티를 끝내고, 클라는 즉시 줌을 푼다. 재조준 RPC는 순서가 보장된다. |
| 조준경 화면 | 조준 중에는 1인칭 총 메시를 숨기고 HUD가 조준경을 그린다. `ScopeOverlayMaterial`이 있으면 그 머티리얼을, 없으면 원형 마스크와 조준선을 쓴다. | 로컬 전용 |

**추정 방법(수직·수평 크기):**
1. AimFinder 스프레이 트레이너의 무기별 상대 상승량(커뮤니티 측정값)을 누적한다. 발 인덱스 k에서의 누적값을 A(k)라고 한다.
2. 밴달 대비 비율 `A_무기(k) / A_밴달(k)`을 구한다. 12발 이후에는 비율을 고정한다.
3. 이 비율을 **밴달 실측 커브**에 곱한다. 밴달처럼 약 10발 이후에는 거의 멈추는 모양이 유지된다.
4. 수평 진폭 = 밴달 2.8° × (AimFinder 드리프트 × 감쇠 발 수 비율).
   - 벌어지기 시작하는 지점은 각 총의 보호 탄 수로 옮긴다.
   - 퍼지는 속도는 감쇠 발 수에 맞춰 늘이거나 줄인다.

카메라 킥(연출), ADS 반동 배율(0.9), 달리기 수직 배율(공개 수치가 없는 총은 6.11 이전 표준값 1.5)도 추정값이다.

## 6. 언리얼 에디터 세팅

총 한 자루 = **무기 BP 1개 + 데이터 에셋 1개 + 픽업 BP 1개**. 코드는 모든 총이 같고, 차이는 데이터 에셋이 만든다.

1. **데이터 에셋**: `DA_*` 20개가 이미 있다. 수치는 에셋에서 튜닝한다(출처는 Source Notes 참고).
2. **무기 BP**: `BP_Vandal`을 복제해 `BP_<무기>`를 만든다(예: `BP_Operator`).
   - Weapon Mesh를 그 총 메시로 바꾼다.
   - Weapon Data Asset에 `DA_<무기>`를 지정한다.
   - 그립 소켓·총구 본 이름이 `GripSocket` / `Muzzle`과 다르면, 데이터 에셋의 Grip Socket Name과 Effects → Muzzle Socket Name을 고친다.
   - 권총(클래식·쇼티·프렌지·고스트·밴딧·셰리프)은 데이터 에셋의 Animation Type이 Sidearm이다. 애님 BP에 권총 포즈가 없으면 우선 Rifle로 바꿔 둔다.
3. **픽업 BP**: `BP_WeaponPickup_Vandal`을 복제하고 Weapon Class를 새 무기 BP로 바꾼다.
   - Pickup Skeletal Mesh를 비워 두면 무기 메시가 자동으로 보인다.
   - 이름 정리: `BP_WeaponPickup_Vandal1`은 스펙터 픽업이다. `BP_WeaponPickup_Spectre`로 바꾸면 헷갈리지 않는다.
4. **연출**(데이터 에셋 → Effects, Fire Montage)
   - 산탄총은 트레이서·탄착이 펠릿 수만큼 나오므로 가벼운 이펙트를 쓴다.
   - 소음기 총(팬텀·스펙터·고스트)은 조용한 발사음을 쓴다.
   - 저격총은 Fire Montage에 볼트/레버 동작이 있으면 좋다(발사 후 조준이 풀리는 동안 보인다).
5. **조준경**(오퍼레이터·마샬·아웃로)
   - 기본 상태로도 HUD가 원형 조준경을 그린다.
   - 전용 조준경을 쓰려면 머티리얼을 만들어 데이터 에셋 → Scope Overlay Material에 넣는다.
     - Material Domain은 User Interface, Blend Mode는 Translucent로 한다.
     - 가운데는 투명, 바깥은 검정, 조준선은 텍스처로 그린다.
   - 원형 조준경 크기·선 두께는 HUD 클래스(`ValorHUD`)의 Scope 항목에서 바꾼다.
6. **조준 방식**(캐릭터 BP → Combat Component → Aim)
   - Toggle Sniper Zoom: 저격총 토글(기본 켬).
   - Toggle ADS: 그 외 총 토글(기본 끔).
   - Auto Re Scope After Shot: 발사 후 자동 재조준(기본 끔).
   - 나중에 설정 메뉴가 생기면 이 값을 세이브 데이터와 연결한다.
7. **확인**(PIE)
   - 불독·스팅어는 ADS로 한 번 클릭하면 3·4점사가 나가고, 누르고 있으면 점사가 반복되는지 본다.
   - 저지·쇼티·버키는 벽에 펠릿 자국 여러 개가 퍼지는지 본다.
   - 클래식·버키는 우클릭으로 보조 공격이 나가는지 본다. 버키는 7.5m 앞에서 퍼진다.
   - 오딘은 누르고 있을수록 빨라지는지 본다.
   - 오퍼레이터는 우클릭으로 2.5배 → 5배 → 해제가 되는지, 쏘면 조준이 풀리는지 본다. 아웃로는 조준이 유지되고 두 번째 발이 튀어야 한다.
   - 반동 확인은 `Valor.Debug.Recoil 1`, 멀티 확인은 PIE 2인 + Play As Client로 한다.

## 6-1. UI 설정 가이드

지금 C++ HUD(`ValorHUD`, 캔버스)는 크로스헤어·조준경만 그린다. 탄약·무기 이름·줍기 안내 같은 정보 UI는 **UMG 위젯**으로 만드는 것을 권장한다(프로젝트 규칙상 블루프린트는 UI에 쓴다).

**위젯 구성 예시(`WBP_ValorHUD`)**

| 영역 | 내용 | 바인딩(블루프린트에서 호출) |
|---|---|---|
| 오른쪽 아래 | 탄약 `25 / 50` | Combat Component → `GetDisplayedMagazineAmmo` / `GetDisplayedReserveAmmo` |
| 탄약 위 | 무기 이름 | `GetEquippedWeaponDisplayName` |
| 탄약 옆 | 재장전 표시 | `IsReloading` |
| 화면 중앙 아래 | 줍기 안내 `[F] 팬텀 줍기` | `GetPickupInView` → 유효하면 표시, 이름은 픽업의 `GetWeaponDisplayName` |
| 조준 중 | 줌 배율 표시(2.5x/5x) | `GetZoomLevel` |
| 조준경 화면 | 탄약·무기 UI를 흐리게 하거나 숨김 | `IsScopeOverlayActive` |

**만드는 순서**
1. 콘텐츠 브라우저에서 위젯 블루프린트 `WBP_ValorHUD`를 만든다.
2. 플레이어 컨트롤러 BP(또는 캐릭터 BP)의 BeginPlay에서 로컬 플레이어일 때만 Create Widget → Add to Viewport로 띄운다.
3. 위젯에서 Get Owning Player Pawn → Cast To ValorCharacter → Get Combat Component를 캐시한다.
4. 탄약·이름은 Tick 바인딩으로 매 프레임 읽어도 가볍다. 줍기 안내(`GetPickupInView`)는 월드를 한 번 훑으므로 0.1초 타이머로 갱신한다.

**원칙**
- UI는 읽기만 한다. 탄약·줍기 판정은 서버가 확정한다.
- 탄약 표시는 예측값이라 쏘는 즉시 줄어든다(서버 결과를 기다리면 RTT만큼 늦게 보인다).
- 크로스헤어는 C++ HUD에 그대로 둔다(탄퍼짐 확대 표시가 스프레이 계산과 연결돼 있다). 모양만 바꾸려면 `ValorHUD`의 Crosshair 항목을 조정한다.
- 조준경 화면에서는 발로란트처럼 탄약 UI를 최소화하면 몰입감이 좋다.

## 7. 정확도를 더 올리려면

추정한 반동 크기는 **실제 게임 녹화 영상**으로 바꾸는 것이 가장 정확하다.
공개 영상은 대부분 오래됐거나(반동 구조가 바뀐 11.08 이전) 반동을 보정하며 쏜 것이라 쓸 수 없었다.

녹화 방법:
- 사격장 벽 앞에 서서 **마우스를 움직이지 않고** 탄창 전체를 힙파이어로 연사한다.
- FOV 103, 1080p 이상, 크로스헤어가 보이게 녹화한다.

이 영상이 있으면 밴달과 같은 방법(프레임별 카메라 회전 + 벽 탄흔 각도)으로 무기별 커브를 실측값으로 바꿀 수 있다.
